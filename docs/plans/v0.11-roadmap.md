# moodle-cli v0.11 Roadmap

As of 2026-10-18.

## Goal and scope

v0.11 makes the CLI a daily driver: a student can stay in the terminal without missing a deadline, see every grade, submit files or online text, read and send messages, reply in forums and see the calendar. Every item below comes from a live audit on 2026-10-18 against a local Moodle 4.5.15, run as a student. Three probes covered every command, and each finding was checked against the database or the web page.

- **In:** the three high-severity bugs, PR #55 follow-ups, the five P0 features, and the cheap, high-value part of P1.
- **Out:** teacher-side features, embedded SCORM/H5P/LTI playback (keep opening those in the browser), a TUI.
- **Rules:** prefer Web Service functions allowed over ajax (verified working with a student session); scrape HTML only when no such function exists; never match English UI text, use CSS classes and data attributes instead.

## Milestone 0: fix the bugs that hide deadlines or grades

The root cause of each of these three bugs was confirmed in source. Each fix ships with a regression test built from real Moodle HTML or JSON.

- [x] **Overdue but still submittable items are missing from `due`/`todo`.** `src/moodle-client-core.ts:418` and `:490` pass `timesortfrom: now`, which drops past events. Fix: look back a window (e.g. 14 days) and keep items the timeline API returns with `overdue:true, actionable:true`; flag them as overdue with the cut-off date. Done when "Overdue quiz prep" (extended to +5 days) shows up in `todo`.
- [x] **`grades list` drops manual grade items and category totals.** `src/scraper.ts:268` skips rows without a link (`if (!link) continue`); `:261` matches the English text "Course total". Fix: classify rows by the `column-itemname` cell's class and level (item, category, course total) and emit unlinked rows with their `feedback`. Done when "Midterm exam 78" with "Solid midterm" and "Exams total" appear, and the rows add up to the total.
- [ ] **First submission is impossible when drafts are on.** `src/moodle-assign-core.ts` around lines 137-153 fetches the `action=submit` confirm page before uploading; before any submission exists Moodle answers "You have not made a submission yet", and draft-stage detection always returns unknown. Fix: detect the draft stage from the assignment settings or the view page's submit button; with `--final`, save the draft first, then fetch the confirm page. Also fix `isSubmitted()` (`:553`), which reads "Nothing has been submitted" as submitted. Done when Essay 1 (drafts + statement) and Group project both accept a draft, then `--final`.

**PR #55 follow-ups (formulas multi-field answers):**

- [x] `--value` on a non-multi-field question is silently dropped: treat a single `--value` as the answer, reject several.
- [x] Remove `calculatedmulti` from `isMultiFieldType` (it is a choice question).
- [x] Add `label` to `AttemptField` from `<label class="subq" for=...>` (e.g. "Unit for part 2") and print it instead of "Answer N".
- [x] Replace the hand-edited fixture with a real formulas attempt page (see Verification).

## Milestone 1: P0 features a daily client cannot lack

Five features, all reachable through Web Service functions that are allowed over ajax and were verified with a student session, except creating a new discussion (form post). The MCP server should gain a read tool for each new read.

| Feature | Proposed commands | Moodle endpoint | Done when |
| --- | --- | --- | --- |
| Messages | `messages list`, `messages show <conversation>`, `messages send <user\|conversation> <text>`, `messages read [--all]` | `core_message_get_conversations`, `core_message_get_conversation_messages`, `core_message_send_messages_to_conversation`, `core_message_send_instant_messages`, `core_message_mark_all_conversation_messages_as_read` | DMs from teacher and peer and the "Team Alpha chat" group conversation are listed, readable, answerable, and unread counts drop to 0 |
| Calendar | `calendar [--days N] [--unit X]`, events merged into `overview`, `calendar --ics` | `core_calendar_get_calendar_upcoming_view` (or `get_calendar_events`) | Course, user and site events ("Guest lecture", "Dentist", "Public holiday") and the BBB session appear, not just action events |
| Online-text submission | `submit <ref> --text <s>` / `--text-file <md\|html>`, combinable with files | `editsubmission` form, `onlinetext_editor` field; reuse the draft and final-confirm flow from Milestone 0 | "Reflection (online text)" can be saved as a draft and submitted; text round-trips with paragraphs intact |
| Forum write | `threads reply <post> <text> [--attach f]`, `forums post <forum> --subject s --text t`, `forums subscribe/unsubscribe <forum>` | `mod_forum_add_discussion_post` (verified), `mod_forum_set_subscription_state`; new discussion via `mod/forum/post.php` form | A student reply and a new discussion appear in `threads show` with the right parent; subscription state toggles |
| Quiz timer | Time left and deadline in `quiz show` / `quiz answer` output and JSON (`time_left_s`, `ends_at`) | Read the timer element and `endtime` data on the attempt page | A timed attempt shows a decreasing time left; finishing after expiry gives a clear message |

| Completion and restrictions | No completion state, no manual toggle; restricted items look normal in lists; `show` on a restricted item exits 5 | Completion column and `complete <ref>` (`core_completion_update_activity_completion_status_manually`); `available:false` + reason |

## P2: after v0.11

These round out a full client but nobody misses a deadline without them. Most have no ajax-allowed Web Service, so they need HTML scraping.

- **Badges:** `badges` from `/badges/mybadges.php`.
- **Participants and groups:** `units members <unit>`, `units groups <unit>`; `core_course_get_enrolled_users_by_cmid` is ajax-allowed, the rest from `/user/index.php`.
- **Private files:** `files private` list, download and upload via `/user/files.php`.
- **Profile and preferences:** full profile in `user`; `prefs` via `core_user_get_user_preferences` / `update_user_preferences` (ajax-allowed).
- **Grade tree:** `grades list --tree` keeping category hierarchy and weights.
- **Unit detail:** course summary, section summaries, teachers, progress % in `units show`.
- **Notes:** read-only, low priority.
- **MCP parity:** today 13 read tools; add messages, alerts, calendar, forum discussion list, quiz read tools, then the write tools behind explicit consent.

## Verification

Every feature should be proven against a real Moodle, not only hand-edited fixtures. The repo already ships `scripts/lab/` (Moodle 5.0: `install.sh`, `generate.php`, `matrix.sh` across themes, languages and disabled services), so extend it rather than adding a new harness: install qtype_formulas and qbehaviour_adaptivemultipart in `install.sh`, and seed the data listed below in `generate.php`. The commands below are how the audit's Moodle 4.5 site was built in a Claude Code cloud container, kept as a reference for a 4.5 variant.

```bash
# 1. Postgres (must not live under a root-only dir)
su postgres -c "initdb -D /var/lib/postgresql/fx/data -U postgres --auth=trust && pg_ctl -D /var/lib/postgresql/fx/data -o '-p 5433 -k /var/lib/postgresql/fx' start"
psql -h /var/lib/postgresql/fx -p 5433 -U postgres -c "create database moodle encoding 'UTF8'"
# 2. Moodle 4.5 + plugins
git clone --depth 1 -b MOODLE_405_STABLE https://github.com/moodle/moodle.git
git clone --depth 1 https://github.com/FormulasQuestion/moodle-qtype_formulas.git moodle/question/type/formulas
git clone --depth 1 https://github.com/maths/moodle-qbehaviour_adaptivemultipart.git moodle/question/behaviour/adaptivemultipart
(cd moodle && COMPOSER_ALLOW_SUPERUSER=1 composer install -q)   # question generators need PHPUnit classes
# 3. Install, then allow cookies over http
php -d max_input_vars=5000 moodle/admin/cli/install.php --non-interactive --agree-license --wwwroot=http://127.0.0.1:8088 --dataroot=$PWD/moodledata --dbtype=pgsql --dbhost=/var/lib/postgresql/fx --dbport=5433 --dbname=moodle --dbuser=postgres --fullname=Test --shortname=Test --adminpass='<admin password>' --adminemail=a@example.com
php moodle/admin/cli/cfg.php --name=cookiesecure --set=0
# 4. Seed data (testing_data_generator script), serve, log in, run the CLI
php -d max_input_vars=5000 -S 127.0.0.1:8088 -t moodle &
MOODLE_BASE_URL=http://127.0.0.1:8088 MOODLE_SESSION=<MoodleSession cookie> node dist/moodle.js due --json
```

Gotchas hit during the audit:

- **Plugin dependency:** qtype_formulas needs qbehaviour_adaptivemultipart; `max_input_vars` must be at least 5000 for install.
- **Login:** the login page has two `logintoken` inputs, so take only the first; set the student's password with `update_internal_user_password`, the generator's password did not work.
- **Quiz seeding:** `quiz_add_quiz_question` left `maxmark` 0, so set slot `maxmark` and quiz `sumgrades`; a generated `calculatedmulti` question breaks attempt start (no datasets).
- **Mail errors:** `email_to_user` errors while seeding messages are harmless.

The seed should create a course with every module type, a graded assignment with feedback comments and file, an extension, a manual grade item and category, forum discussions with replies and an attachment, DMs and a group conversation, course/user/site calendar events, a badge, a private file, a formulas quiz (multi-part, separate unit field), and hidden and restricted pages. Acceptance for v0.11: each Milestone 0-2 item has a passing check against the lab, and `moodle coverage` reports no failures.

## Implementation status (2026-10-18)

The current implementation follows the five-day scope above. It has not been released; the package version remains 0.10.0.

Delivered:

- Overdue actionable deadlines in `due`, `todo` and the dashboard; manual grade items and category totals without English-title matching.
- PR #55 follow-ups, including actual formulas HTML captured from the lab, field labels and single-value validation.
- Messages list/show/send/read, calendar with ICS and dashboard events, online text with optional file uploads, forum reply/post/subscription, and quiz countdown/deadline output. The remote MCP adds only read tools for conversations and calendar.
- Assignment descriptions, submitted text/files/comments and separate feedback; limits and dates when Moodle exposes them; submission show/remove; manual completion and readable restriction reasons.
- Forum attachments and metadata, consistent course-module ids, end-of-thread pagination, resource names/unit ids, nested download paths, notification bodies/read state, browser-opener fallback and dry-run behavior.

Known limits:

- First `--final` saves the work before loading the final confirmation page, and existing drafts can be saved and finalized. A first **draft-only** save remains refused on stock Moodle when its draft setting is unknown. The student view hides the submit button before content exists, the edit form exposes no draft flag, and assignment-settings Web Services are not AJAX-enabled. Guessing would risk submitting for grading without `--final`. This is why the first-submission checkbox above remains open.
- A submission statement may become visible only after the first save. Plans report `statement_pending`; a refusal after saving includes the saved receipt and an exact retry command.
- Stock attempt pages expose a countdown, not always an absolute deadline. `ends_at` uses the HTTP server clock and can differ by up to two seconds between reads; an explicit Moodle end timestamp takes precedence.
- Assignment cut-off settings and limits on locked work are omitted when the student-facing site does not expose them. Deadline rows show the due date and overdue state; they do not fabricate a hidden cut-off date.

As specified in the suggested order, the rest of Milestone 2 and the remaining low-priority backlog stay in 0.12: additional activity readers/actions, book chapters and body-text search, quiz select/check/attempt-reference work, current/past unit filtering and auth diagnostics. P2 remains deferred.

Reproduce validation with `npm run check`, `npm test`, `npm run build`, `npm run pack:check`, `scripts/lab/matrix.sh` and `node scripts/lab/acceptance.mjs` against a freshly generated lab. The acceptance report explicitly distinguishes passing checks from the first-draft limitation.

Validation completed: **875 tests passed, 1 platform-specific test skipped; 16 lab acceptance checks passed with 1 recorded limitation; all 6 Moodle variants passed**. See [the validation and review record](../reviews/v0.11/README.md) for commands, scope and limitations.
